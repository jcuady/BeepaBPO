## 5. Workflows (end-to-end)

### 5.1 Leave request (employee → team lead → HR)
1. Employee submits at `/app/my/leave` → `createLeaveRequest` action.
2. `leave_requests` row inserted with `status=pending`.
3. `approval_requests` row inserted (workflow code=`leave`).
4. `notify_leave_request` trigger fires → in-app notification to the requester.
5. Team Lead sees it at `/app/leave` → clicks Approve → `advanceApprovalRequest`.
6. Step 2 (HR) — same flow.
7. Notification to requester at each step.
8. Status flow: `pending` → `manager_approved` → `hr_approved` → `approved`.

### 5.2 Cash advance (employee → HR → Finance)
1. Employee submits at `/app/my/cash-advances` → `createCashAdvanceRequest` action.
2. `cash_advance_requests` row + `approval_requests` (workflow `cash_advance`).
3. HR approves at `/app/cash-advances`.
4. Finance approves → `released`.
5. Final state: deductions hit payroll.

### 5.3 Attendance correction (employee → HR)
1. Employee at `/app/my/attendance` → "Request correction".
2. `attendance_correction_requests` row.
3. HR/Supervisor at `/app/attendance/corrections` → Approve.
4. Updates `attendance_records` clock_in / clock_out.

### 5.4 Payroll period
1. Finance at `/app/payroll/periods` → run wizard creates period (`status=preparing`).
2. Records for each employee seeded.
3. `calculate_payroll_record` RPC (auth required) — stub engine v1.
4. Submit for review → status=`review`.
5. Finance Approve → status=`approval`.
6. Owner Approve → status=`finalized`.
7. Payslips + PDF generated.

### 5.5 Ticket
1. Created at `/app/my/requests` or `/app/client/tickets`.
2. SLA `sla_due_at` set on insert via trigger.
3. Internal staff assigns at `/app/tickets/[id]`.
4. Client replies → ticket_messages.
5. Resolved → `resolved_at` set.
6. Realtime refresh on `/app/tickets` and `/app/client/tickets` via `<RealtimeRefresh>`.

### 5.6 ATS
1. Recruiter creates `job_posts` at `/app/recruitment/jobs`.
2. Public applies at `/careers/[slug]` → `applyToJob`.
3. Recruiter reviews at `/app/recruitment/applicants` → stage form.
4. Hire: `HireConvertButton` → creates employee + employment.

## 7. VAPID / push notifications

VAPID keys (generated 2026-10-06, **rotated 2026-10-14** — the originals were
committed to this file in plaintext and are treated as compromised):
- Public: **not recorded here.** Read it from `.env.local` or Vercel.
- Private: **not recorded here, and never should be.** `VAPID_PRIVATE_KEY` is
  server-only key material; the moment it is in a repository it must be rotated,
  because git history keeps it forever and a public clone has already pulled it.
- Subject: `mailto:admin@beepabpo.com`

Generate a replacement with `npx web-push generate-vapid-keys`, then set
`VAPID_PRIVATE_KEY` + `NEXT_PUBLIC_VAPID_PUBLIC_KEY` in `.env.local` **and** in
the Vercel project env. Existing browser push subscriptions are invalidated by
the rotation — subscribers re-subscribe on next load.

Verified via `node scripts/audit/test-vapid.mjs`:
- `webpush.setVapidDetails` accepted the keys.
- `webpush.sendNotification` accepted the request shape.

Notification preferences (per user, 2026-10-06 audit):
- All 13 demo users now have a `notification_preferences` row.
- `in_app_enabled = true` for everyone.
- `push_enabled = true` for everyone (gated on actual browser subscription).
- `email_enabled = true` for: owner, super_admin, hr, finance, operations, team_lead.
- `email_enabled = false` for: recruiter, sales, marketing, employee, client_admin, client_viewer, applicant.

Browser subscribe path: `/app/my/notifications` → "Enable push" button → `usePushSubscription` → POST `/api/push/subscribe` → upsert `push_subscriptions` row.
